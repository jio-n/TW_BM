# 分野を変えて使う検索・確認プロトコル

## 1. 質問から検索計画を作る

テーマを対象、入力、求める出力、研究方法、期間・言語へ分解する。採用条件は出力・実験内容で決め、モデル名や引用数だけで決めない。例えば「材料損傷の種類分類」なら、損傷量の回帰、正常／異常だけの判定、原因分類を含むかを先に定義する。

語群は次の形で保存する。実際の検索式は各DBの検索フィールド・構文に翻訳し、`queries.csv` に独立した行として登録する。

| 語群 | 記録する内容 | 検索式への使い方 |
|---|---|---|
| 対象 | 正式名称、略語、材料・対象物、日本語・英語 | 同義語をORでつなぐ |
| 目的・出力 | classification、type、category等と実際の出力名 | 原則、対象とANDで組む |
| 方法 | 指定手法と旧称・周辺手法 | 方法あり／なしの式を両方置く |
| 見落とし対策 | 類似名、旧用語、地域表現 | 別の短い式で補う |

最初から長いAND条件へ絞り込みすぎない。既知の直接関連論文3–10本を検索前に登録し、DB収録を確認した上で試し検索に回収されるか確認する。検索後に見つけた論文は `posthoc` とし、独立した回収試験の分母へ加えない。

## 2. 情報源の役割を決める

以下は情報源の選択例であり、全テーマで全DBを義務付ける一覧ではない。検索機能・アクセス条件・API仕様は実行時に公式説明で確認する。

| 役割 | 選択例 | 記録上の注意 |
|---|---|---|
| 分野横断の発見 | Google Scholar、OpenAlex、Crossref | 検索範囲・順位・引用索引の違いを残す |
| 分野の中心DB | IEEE Xplore、ACM DL、PubMed、分野に応じた索引 | テーマへの適合性を理由に選ぶ |
| 出版社・原著 | ScienceDirect、SpringerLink、MDPI、学会公式 proceedings | 索引での発見と原著確認を分ける |
| 日本語・国内研究 | J-STAGE、CiNii Research、大学リポジトリ | 和英両方の語群を試す |
| 最新研究 | arXiv、分野別preprint、著者・会議の公開ページ | 出版版との重複、査読状態、公開日を区別する |
| 引用による拡張 | 参考文献、被引用索引、後続版、レビューの引用 | seed・方向・取得集合・選別数を記録する |

大分類ごとに「採用する／このテーマでは使わない／アクセス制約あり」を理由付きで計画する。`coverage_cell` は例えば `対象群×入力×出力×方法×年代×言語` の未充足領域を表す。予定した式を実行前に台帳へ入れることで、検索していない領域も画面に残る。式を置かなかった領域は自動発見できないため、計画そのもののレビューが必要である。

## 3. 小さく試してから範囲を広げる

1. 各式の最初の10–20件で、検索フィールド・引用符・AND/OR・期間・並び順が意図どおりか確認する。
2. 取得した全結果をhitsへ記録する。良さそうなものだけを残さない。DBの総数、概数、返却件数、エラーを区別する。
3. 関連度順と新着順を別の検索式／集合として計画する。関連度順の上位だけで新しい低引用論文を取りこぼさない。
4. 題名・抄録で採否を決め、直接関連、可能性あり、保留、除外を理由付きで記録する。
5. 有望な式、未充足カテゴリ、ユーザー指定へ次の取得量を割り当てる。検索結果は順位を追い、途中のページ抜けを埋める。

絶対順位を返さないAPIでは、同一の安定したカーソル列に沿って取得順序を記録できる場合に限り、累積順位を使う。それも確認できなければ `status=diagnostic`、`semantics=uncertain` とし、rankは返却順序の記録にとどめる。確認済みの集合充足として集計しない。

## 4. 本文確認と引用探索を接続する

直接関連論文、関連するレビュー、方法や時期の異なる代表例をseedにする。優先点だけで同じ研究群へ偏った場合は、ユーザーtasksで別群のseedを指定する。`queries.seed_paper_id` と `direction`、`citation_checks` で経路を残す。

後方引用は原著の参考文献、前方引用は利用可能な引用索引を確認する。索引が異なれば被引用集合も異なる。前方引用0件を「後続研究が存在しない」と読み替えない。引用深度2なら、1段目で新しく採用したseedからの2段目を別の検索集合として記録する。

本文では、定義した出力が実験で本当に評価されているかを先に確認する。成績は指標、値、データ、分割、クラス、条件、原文の表・節とセットにする。未取得は著者版・機関リポジトリ等を調べ、見つからなければ保留と取得制約を残す。

## 5. 各周回の終了時に監査する

| 点検 | 合格のために必要な証拠 |
|---|---|
| 計画どおり探したか | 必須DB・検索式・領域の実行記録、未実施理由 |
| 結果を選り好みして消していないか | runの返却数とhitsの行数が一致 |
| 同じページで件数を増やしていないか | 同一集合の順位和集合、重複を残した発見経路 |
| 検索式が目的を満たすか | 意味の確認、事前登録した既知論文の回収、別語群の試行 |
| まだ読むものがあるか | 未選別・保留・未読・抽出不足・取得失敗の状態 |
| 拡張が進んだか | seed別・方向別の集合数と確認数、追加候補の採否 |
| 完了の誤表示がないか | 必須抽出項目と根拠、作業完了の参照ID、更新履歴 |

低い候補率は、その検索式・その順位帯の追加価値が低下したという材料である。別語群・別DB・最新順・引用経路も試し、未充足領域がなくなったかを合わせて判断する。世界全体の残数や、根拠のない「網羅率95%」へ変換しない。

最終報告は「完了した予定範囲」「既知の残作業」「アクセス制約」「次の有望な経路」「未探索の可能性」を分ける。必要なら別の担当者が除外の一部と重要な採用根拠を再判定し、意見の相違と修正をevidence・履歴へ残す。
