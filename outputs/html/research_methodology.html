01 / scope

「何の種類か」を出力する研究に絞る

INPUT画像、または画像を含む入力
工具実写工業画像任意のセンサ・プロンプト
→
OUTPUT摩耗・欠陥のカテゴリー名
逃げ面摩耗チッピング傷・亀裂複合クラスも可
判断軸採用する課題区別して管理する課題
出力種類名の単一ラベル／複数ラベル分類、候補付き種類VQA量・寿命・程度だけの予測、正常／異常だけの二値判定
工具の入力推論時に工具実写を使用。実写＋センサは別区分信号のスペクトログラムだけ、正解測定時だけの工具写真
工業のモデルViT等、VLM由来特徴、MLLMを主構成で分類比較モデルだけに使う方式を主提案として重複計上しない
関連研究領域検出・分割、未知カテゴリー発見を別表へ検出mAP・IoUを画像分類Accuracyに置き換えない
分類軸は独立している

CNNかViTかという構造、画像のみか画像＋センサかという入力、単一ラベルか複数ラベルかという出力は別の軸。ViTもVLMも深層学習であり、「深層学習対vision」という二分はしない。

02 / history

実際の調査を、時点ごとに区別する

広域調査 → 問いを絞る

商用製品と工具状態研究を広く集めた後、ユーザーの意図に合わせて「摩耗量・寿命」から「摩耗種類の分類」へ再選別。工業欠陥の視覚Transformer／VLM／MLLMへ対象を拡張した。

初回重点調査 → 原著の成績を確認

Web横断の一般語・ドメイン指定検索から出版社、著者版、機関リポジトリへ進んだ。工具55行・工業51行の検索／直接確認ログ。各DBの独立した検索集合を全件取得する運用は不足していた。

引用追跡 Round2 → 発見経路を台帳化

主要16本×前方・後方の32方向を確認。128実行ログ、279候補発見行、276引用・関連・異版行、76取得試行。16方向は申告した索引集合を全件一次選別、残16方向は部分確認。

DB内検索の試行 → 未取得範囲を見える形に

Google Scholar／IEEEの公式画面とJ-STAGE／CiNii／arXivの公式APIを実行。検索・取得順位・候補・意味検証を分離した。48実行ログを残し、追加候補は本文確認待ちに置いた。

仕様に書いたDB名を、検索実績と取り違えない

過去の未実施・未記録を後から「調査済み」へ変更していない。初回、引用追跡、DB検索試行は別の記録であり、ログ行数を足して独立論文数にはしない。

根拠：従来の方法Round2監査

03 / workflow

毎回使える、8段階の探索と確認

問い・採否を固定入力、出力、モデル、期間、境界事例を定義
語群と検索枠を設計同義語・日本語／英語・広い式／狭い式
DBと引用を探索検索フィールド・順位・前後引用を記録
重複と異版を照合発見経路を保持しDOI・題名・著者を確認
題名・抄録で選別種類／段階／量、実写の有無を切り分け
本文で成績を抽出ラベル・指標・値・分割・図表位置を保存
未処理と根拠を監査未実施・未取得・未判定・根拠抜けを点検
差分を公開し再探索追加候補と不足セルを次の周回へ戻す
検索語は、全条件を最初から必須にしない

対象語＋課題語の広い式、具体的ラベルを足した式、モデル語を足した式を併用する。必要に応じて語群を一つ外し、用語が異なる研究を補う。複雑な式は単純式と返却題名で意味を確認する。

工具 / 広く：       "tool wear" classification image
工具 / 種類を追加： "tool wear" "chipping" classification image
工業 / ViT：        "defect classification" "vision transformer"
工業 / VLM：        "defect classification" "vision-language"
国内：              工具摩耗 画像 ／ 外観検査 欠陥 分類 Transformer
arXiv API：         all:"tool wear" AND all:classification

これらは今回実行した式の例。各DBの構文・対象フィールドに合わせて変換する。詳細プロトコル

04 / databases

5つの論文サイトで、検索経路を実証する

サイト経路取得範囲限界
Google Scholar公式画面・4式各上位10件、延べ40枠総数は概数。2ページ目以降未取得。年フィルタ未指定。
IEEE Xplore公式画面・2式成功工具25/30件、工業ViT25/77件残5／52件。初回エラーは0件として数えない。
J-STAGE記事API・6式＋追加ページ延べ66書誌大半は上位10件。重点候補以外の詳細選別は未完了。
CiNii ResearchOpenSearch・6式＋追加ページ延べ60書誌、工業ViT40/51件残11件。通常画面GETは6式とも空応答。
arXiv公式API・18式／19取得診断込み120枠、87候補を題名・抄録確認工具分類8件、ViT分類11件は当該式全件。他は一部ページ。
48実行 ≠ 48件の論文

通常取得32、失敗7、重複接続確認2、構文診断7。順位台帳366行には重複・診断を含み、それらを除く取得枠は275。関連文献数でも独立論文数でもない。

成功応答でも、式の意味を確認

arXivの複合式で別分野が多数返ったため、先頭7式を診断扱いにし、単純式で再試験した。HTTP 200だけで有効な検索と判断しない。

サイトとAPIの違いを記録

CiNiiは通常画面GETが空応答でもOpenSearchで取得できた。公式仕様のappid必須と、今回の無指定GET成功は区別して残した。

根拠：48実行ログ取得順位試行報告

06 / evidence

主張から原資料へ戻れる形にする

TRACEABILITY論文ID → Claim ID
→
PRIMARY SOURCESource ID → 原著の表・図・節
必ず対にする情報理由
指標名＋数値＋単位Precision、Accuracy、MCC、F1、mAPを混ぜない
ラベル＋推論入力＋評価単位画像全体、正解ROI、領域対応後、4択VQAを区別
データ規模＋分割＋未知条件画像ランダム分割と工具・ロット単位の外部検証は別
確認状態＋本文位置＋原資料URL本文、抄録、検索結果のみを区別。未確認を0や非公開にしない
自動監査のPASSは、網羅性の合格ではない

検索IDと順位件数、失敗の0件化、診断式の誤った昇格を機械検査する。意味理解、原文の値の正しさ、研究の網羅性は別途レビューが必要。故意の3種の誤りを検出するself-testも実施した。

07 / next

次の調査へ、そのまま持ち出す

優先して埋める残件

  1. IEEE・CiNii・arXiv等の残ページを取得・選別。
  2. 未実施3枠、工具・産業・年代別の追加語を検索。
  3. 新候補と保留の本文から種類ラベル・成績を抽出。
  4. 既知論文の収録確認、除外の独立再判定を実施。

新テーマでの利用手順

  1. 仕様テンプレートへ入力・出力・除外条件を書く。
  2. 検索行列と検証用seedを先に固定する。
  3. 検索、順位、候補、本文、根拠を記録する。
  4. 監査し、実施範囲と残件を添えて公開する。
